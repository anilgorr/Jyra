Build DigiSignal's provider abstraction layer.

CORE PRINCIPLE

DigiSignal must not depend directly on one data vendor, API, scraper or Apify Actor.

Business logic asks for a CAPABILITY.

The Provider Router decides which provider satisfies it.

PROVIDER ROUTER

Selection should consider:

capability
enabled status
priority
estimated cost
recent success rate
quality score
latency

Support provider fallback.

Example:

Research Planner requests JOB_SEARCH.

Provider Router chooses Provider A.

If A fails and Provider B exists, fallback according to configuration.

USAGE

Every provider request should eventually produce a usage record.

Do not yet build production external providers.

For this milestone create deterministic mock adapters for:

WEB_SEARCH
WEBSITE_CRAWL
JOB_SEARCH

ACCEPTANCE CRITERIA

Verify:

- business logic can request a capability
- provider router selects a configured provider
- provider can be changed without altering business logic
- fallback works
- provider usage can be logged
- tests use deterministic mock providers
