JYRA — ADAPTIVE RETRIEVAL PRODUCTIONIZATION 01
PROMOTE VALIDATED TAVILY → EXA FALLBACK INTO NORMAL RESEARCH PATH

PURPOSE

The retrieval architecture has now been validated.

Retrieval Fallback Validation 01 established:

- Tavily runs first.
- Exa runs only when Tavily retrieval is insufficient or Tavily fails.
- Maximum two provider calls per research question.
- 7/7 frozen retrieval controls retrieved in BOTH preserved validation runs.
- 100% final retrieval recall.
- 1 Tavily-only result.
- 1 Exa-only recovery.
- 5 events found by both providers.
- 0 controls missed by both.
- Wrong entity accepted = 0.
- Seller content accepted = 0.
- Cross-provider deduplication passed.
- Publisher/provider separation passed.

Decision:

ADAPTIVE TAVILY → EXA RETRIEVAL VALIDATED.

Exa is currently experimental/development-only and has NOT been
permanently added to normal research routing.

GOAL OF THIS MILESTONE:

Promote the validated adaptive retrieval architecture into JYRA's
NORMAL research execution path:

ResearchQuestion
→ Tavily primary
→ retrieval sufficiency evaluation
→ Exa fallback only when required
→ merge/dedupe
→ normal evidence pipeline

After this milestone, RETRIEVAL SHOULD BE FROZEN for the current MVP
unless a later end-to-end benchmark reveals a new demonstrated defect.
