4. FACT LAYER PRINCIPLE
==================================================

A FACT is an observed claim supported directly by evidence.

A FACT is NOT:

buyer intent

opportunity interpretation

sales hypothesis

signal

prediction.

Example:

VALID FACT:
"Company appointed Jane Doe as CISO on May 3, 2026."

INVALID FACT:
"Company is strengthening cybersecurity."

VALID FACT:
"Company raised $50M Series C."

INVALID FACT:
"Company has funded a security program."

The latter requires additional security-specific evidence.

7. CLAIM BOUNDARY
==================================================

Every extracted fact must be directly supported by the evidence.

The extractor may normalize wording.

Example:

==================================================
9. SELLER-AS-BUYER SAFETY
==================================================

Evidence describing what a company SELLS must not become evidence that
the company is BUYING the same thing.

Examples:

"We provide Managed SOC services"

must NOT become:

"Company is investing in Managed SOC."

"We offer cybersecurity consulting"

must NOT become:

"Company has a cybersecurity buying initiative."

"We help customers migrate to Azure"

must NOT become:

"Company is migrating its own infrastructure to Azure."

Preserve source/entity role semantics.

==================================================
12. EVENT DATE MODEL
==================================================

Separate:

PUBLISHED_AT

RETRIEVED_AT

OBSERVED_AT

EVENT_AT.

These are different concepts.

EVENT_AT must represent when the event actually happened.

PUBLISHED_AT = source publication timestamp.

RETRIEVED_AT = when JYRA fetched it.

OBSERVED_AT = when JYRA observed a timeless/current-state fact.

Never silently substitute one for another.

==================================================
13. EVENT FACT DATE REQUIREMENT
==================================================

Event-style facts require a defensible event date or explicit temporal
relationship.

Examples:

PERSON_ROLE_CHANGE
FUNDING_EVENT
ACQUISITION
SECURITY_INCIDENT
TECHNOLOGY_MIGRATION
PROGRAM_INVESTMENT

should NOT become current event signals merely because JYRA observed
the page today.

If event date cannot be established:

eventDate = UNKNOWN

and temporal signal activation must follow existing safe behavior.

==================================================
14. OBSERVATION DATE
==================================================

Observation date is appropriate for timeless/current-state facts such
as:

company currently lists a technology

current website technology

current employee range

current service description

current leadership roster

when no change event is claimed.

Observation date must NOT convert a state observation into a recent
change event.

==================================================
15. DATE EXTRACTION
==================================================

Extract event date from:

explicit date in claim

explicit relative date with defensible source date

structured metadata tied to the event

clearly stated announcement timing.

Do NOT infer event date from:

retrieval timestamp

page crawl timestamp

database insertion timestamp.
