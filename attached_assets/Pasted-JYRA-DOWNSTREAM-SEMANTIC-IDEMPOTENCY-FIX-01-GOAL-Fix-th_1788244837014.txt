GOAL

Fix the known replay/idempotency defect in the downstream opportunity
pipeline.

The previous frozen 10-control replay correctly reused research state
with ZERO new provider calls, stable facts, stable signals and stable
clusters.

10 new opportunity-history rows
10 new WHY versions

UNCHANGED MATERIAL INTELLIGENCE
→ NO NEW SEMANTIC HISTORY EVENT
→ NO NEW WHY VERSION
→ NO DUPLICATE RECOMMENDATION

This task is ONLY about semantic idempotency.

==================================================

semantic fingerprint.

Runtime timestamps must not cause false changes.

account/opportunity.

8. CANONICALIZATION
==================================================

Before hashing/fingerprinting:

sort unordered ID arrays

normalize null/undefined consistently

normalize enum/string representation

normalize date representation

exclude volatile metadata

use stable object-key ordering.

Same semantic state must always produce the same fingerprint.

==================================================
9. OPPORTUNITY HISTORY
==================================================

Opportunity history should represent a MATERIAL CHANGE.

Examples of legitimate new history:

WATCH → RISING

RISING → SURGING

new material signal

material signal expires

confidence materially changes

meaningful opportunity score/state change

material contradiction appears

material opportunity hypothesis changes.

Examples that should NOT create history:

same evaluation reruns

same facts/signals reprocessed

page refresh

worker retry

same research replay

timestamp-only changes.

  material intelligence state

Before inserting history:

compare against latest semantic snapshot/fingerprint.

UNCHANGED_SEMANTIC_STATE.

==================================================
11. WHY VERSIONING
==================================================

WHY versions should represent a material explanation change.

Do NOT create a new WHY version because the WHY generator ran again.

Canonical WHY identity should depend on material content/support such as:

opportunity/account
WHY semantic content
supporting signal IDs
supporting fact IDs
supporting evidence IDs
confidence/material state
WHY classification/state.

Do not depend on generation timestamp.

==================================================
12. WHY CONTENT NORMALIZATION
==================================================

Avoid false versions from harmless formatting differences where safe.

At minimum normalize deterministic structured WHY representation before
fingerprinting.

Prefer structured semantic fingerprint over hashing display prose alone.

==================================================
13. WHY WRITE RULE
==================================================

If the new WHY semantic fingerprint equals the current WHY version:

DO NOT CREATE NEW VERSION.

If supporting intelligence or material explanation changes:

CREATE NEW VERSION.

==================================================

offering

recommendation type
material rationale/intelligence state.

Execution timestamp must not define recommendation identity.

recommendation state.
