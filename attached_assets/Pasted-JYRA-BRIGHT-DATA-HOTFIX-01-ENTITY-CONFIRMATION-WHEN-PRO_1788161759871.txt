==================================================
OBJECTIVE
==================================================

Allow a Bright Data firmographic result to become CONFIRMED even when the
provider does not return the LinkedIn URL, provided the complete identity
chain gives strong deterministic evidence that the returned record belongs
to the requested canonical company.

Do NOT simply convert every PROBABLE result to CONFIRMED.

==================================================
1. REQUESTED IDENTIFIER IS EVIDENCE
==================================================

The submitted LinkedIn company URL is itself part of the provider request
provenance.

Preserve:

requested_linkedin_url

requested_company_id

requested_company_name

requested_canonical_domain

requested_website_url

Do not depend on Bright Data echoing the submitted identifier.

==================================================
2. NORMALIZE LINKEDIN URL
==================================================

Normalize the submitted LinkedIn company URL before comparison.

Handle safely:

www.linkedin.com/company/example
linkedin.com/company/example/
country-specific LinkedIn host variants
query parameters
fragments

Preserve the original URL in provenance.

Never derive canonical company domain as linkedin.com.

==================================================
3. ENTITY CONFIRMATION MODEL
==================================================

Evaluate independent identity evidence.

Strong identifiers:

A. requested LinkedIn URL was already associated with the canonical company
   with acceptable provenance/confidence

B. returned official website/domain exactly matches existing canonical domain

C. returned company name strongly matches existing canonical company name

Supporting identifiers:

D. geography consistent
E. industry consistent
F. provider/company identifiers consistent
G. known aliases consistent

Contradictions must also be evaluated.

==================================================
4. CONFIRMED RULE
==================================================

A Bright Data result may be CONFIRMED without returned LinkedIn URL when:

1. The request used an existing LinkedIn company URL associated with the
   canonical company

AND

2. At least one additional strong independent identifier agrees.

Preferred confirmation:

requested LinkedIn identity
+
exact returned domain match

Alternative:

requested LinkedIn identity
+
strong company-name match
+
no material contradictory identity evidence

Exact domain agreement should carry greater weight than fuzzy name agreement.

==================================================
5. DO NOT CONFIRM WHEN
==================================================

Remain PROBABLE or AMBIGUOUS if:

LinkedIn URL was newly guessed

LinkedIn URL provenance is weak

company name is generic

returned domain conflicts

geography materially conflicts

multiple companies plausibly match

parent/subsidiary ambiguity exists

provider result appears to represent a different legal/company entity

==================================================
6. WRONG ENTITY
==================================================

If returned data materially contradicts canonical identity:

classify:

WRONG

Do not attach firmographics.

Examples:

different official domain
clearly different company
different geography combined with weak name match
parent company returned instead of requested subsidiary without evidence

==================================================

Do not manufacture returned_linkedin_url from the request.

This distinction is important.

The submitted LinkedIn URL belongs to request provenance.

It must NOT be represented as if Bright Data returned it.
