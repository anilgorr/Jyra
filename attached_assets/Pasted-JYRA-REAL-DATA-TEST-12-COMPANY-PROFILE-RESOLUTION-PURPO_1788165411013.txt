JYRA — REAL DATA TEST 12
COMPANY PROFILE RESOLUTION

PURPOSE

Build a generic capability that converts an existing canonical company
identity into a VERIFIED LinkedIn company profile URL.

This solves the bottleneck demonstrated by Real Data Test 11:

10 companies tested
1/10 usable LinkedIn company URLs
Bright Data quality when identifier exists: PASS
Bright Data cost: excellent
Firmographic provider replacement: NOT justified

We need:

Company
→ COMPANY_PROFILE_RESOLUTION
→ verified LinkedIn company URL
→ Bright Data COMPANY_FIRMOGRAPHICS

This milestone stops BEFORE Bright Data firmographic enrichment.

==================================================
1. NEW GENERIC CAPABILITY
==================================================

Add:

COMPANY_PROFILE_RESOLUTION

Do NOT call this:

LINKEDIN_LOOKUP

The business capability is:

resolve external company profiles/identifiers.

LinkedIn is the first target profile type.

Future profile types may include:

Crunchbase
GitHub organization
company careers site
regulatory/legal entity
other company profiles

Provider Router must remain provider-independent.

==================================================
4. RESOLUTION STATES
==================================================

Use:

VERIFIED
PROBABLE
AMBIGUOUS
NOT_FOUND
WRONG

VERIFIED must require strong identity agreement.

PROBABLE must NOT automatically become an authoritative identifier.

AMBIGUOUS must preserve candidates for review.

NOT_FOUND is valid.

Never guess.

==================================================
5. FIRST PROVIDER STRATEGY
==================================================

Use existing providers before adding another vendor.

Preferred initial resolver:

TAVILY → WEB_SEARCH

The Research Planner / Provider Router should invoke Tavily through the
existing provider architecture.

Do NOT scrape LinkedIn directly.

Do NOT use browser automation.

Do NOT bypass LinkedIn access controls.

We are discovering publicly indexed company profile URLs.

==================================================
6. SEARCH STRATEGY
==================================================

Generate deterministic identity-resolution searches.

Examples conceptually:

site:linkedin.com/company "Company Name"

site:linkedin.com/company "Company Name" "companydomain.com"

"Company Name" LinkedIn company

Use canonical domain when available because it is strong disambiguation
evidence.

Maximum:

2 Tavily searches/company

Prefer one strong query first.

Only use second query if first is insufficient.

==================================================
7. SEARCH RESULT ≠ VERIFIED PROFILE
==================================================

Critical rule:

A Tavily result containing:

linkedin.com/company/xyz

is only a CANDIDATE.

It is not automatically the correct company.

Candidate must pass entity verification.

==================================================
8. LINKEDIN URL VALIDATION
==================================================

Accept company profile forms only.

Examples:

linkedin.com/company/{slug}

Normalize:

www host
country-specific LinkedIn host
scheme
trailing slash
query
fragment

Reject:

/in/
/jobs/
/posts/
/feed/
/learning/
/school/ unless explicitly supported later
/person profiles
search URLs
redirect URLs

Never set:

canonical_domain = linkedin.com

==================================================
9. ENTITY VERIFICATION
==================================================

Score/verify candidate using independent evidence.

Strong evidence:

A. company name agreement

B. canonical domain agreement visible in search/result/source metadata

C. official company website links to same LinkedIn company profile

D. LinkedIn candidate references the same official website/domain

Supporting evidence:

country
city
industry
description
aliases
parent/subsidiary relationships

Contradicting evidence must reduce confidence.

==================================================
10. OFFICIAL WEBSITE EVIDENCE
==================================================

If the canonical website already contains a LinkedIn company link,
that should be considered high-authority identity evidence.

Use existing stored website evidence first if available.

Do not automatically crawl all websites.

If existing evidence contains an outbound LinkedIn company URL:

validate and use it.

Only use WEBSITE_CRAWL later if economically justified and needed.

For this test:

Apify calls must remain 0 initially.

==================================================
11. VERIFICATION POLICY
==================================================

VERIFIED examples:

company name matches
+
canonical domain independently matches

OR

official canonical website links directly to candidate LinkedIn profile

OR

multiple independent strong identity observations converge.

PROBABLE:

strong name match
+
supporting geography/industry
but domain confirmation unavailable.

AMBIGUOUS:

multiple plausible LinkedIn companies
or weak/generic company name.

WRONG:

material identity contradiction.

==================================================
12. PLATFORM RESULT SAFETY
==================================================

A result such as:

https://linkedin.com/company/infravault

must become:

profile_type = LINKEDIN_COMPANY
profile_url = ...

It must NEVER become:

canonical_domain = linkedin.com

This regression has already been identified in earlier testing.
